We’ll produce a detailed specification covering the build system, dataset pipeline, model architecture, and training loop, all in pure Rust targeting a single RTX 5090 under Windows/MSVC with CUDA 12.x. The design prioritizes maximum hardware utilisation, explicit group‑query attention, FlashAttention‑3 where practical, and a memory‑mapped token stream to sustain >70 k tokens/s over 2 B tokens.

## 1. Build System & CUDA/ MSVC Integration

The `Cargo.toml` uses `candle` as the primary tensor framework. It brings its own CUDA bindings (`candle-core/cuda` feature), linking `cublas`, `curand`, and optionally `cudnn`. Any custom CUDA kernel (e.g., a faster FlashAttention‑3 forward) is compiled by `nvcc` inside `build.rs` and linked statically.

### `build.rs` – Compiling Custom CUDA Kernels and Linking Toolkit Libraries
The script locates the CUDA toolkit, compiles `.cu` files with `nvcc`, and ensures the CUDA runtime libraries are available to the linker. The example shows a custom FlashAttention‑3 forward kernel.

```rust
// build.rs
use std::env;
use std::path::PathBuf;

fn main() {
    // Locate CUDA installation from CUDA_PATH environment variable
    let cuda_path = env::var("CUDA_PATH")
        .or_else(|_| env::var("CUDA_HOME"))
        .unwrap_or_else(|_| "C:\\Program Files\\NVIDIA GPU Computing Toolkit\\CUDA\\v12.5".to_string());
    let cuda_lib_path = PathBuf::from(&cuda_path).join("lib").join("x64");
    let cuda_include = PathBuf::from(&cuda_path).join("include");

    // Tell cargo to link the necessary CUDA libraries (they are needed at runtime)
    println!("cargo:rustc-link-search=native={}", cuda_lib_path.display());
    println!("cargo:rustc-link-lib=cublas");
    println!("cargo:rustc-link-lib=cudnn");
    println!("cargo:rustc-link-lib=curand");
    println!("cargo:rustc-link-lib=cudart");

    // Compile custom CUDA kernel(s) – e.g., flash_attn_fwd.cu
    cc::Build::new()
        .cuda(true)
        .file("kernels/flash_attn_fwd.cu")
        .include(&cuda_include)
        .flag("-gencode").flag("arch=compute_90a,code=sm_90a")  // Blackwell SM 90a (adjust for RTX 5090)
        .compile("flash_attn_kernels");

    // Re-run if CUDA files change
    println!("cargo:rerun-if-changed=kernels/flash_attn_fwd.cu");
    println!("cargo:rerun-if-env-changed=CUDA_PATH");
}
```

*Note:* In practice, `candle`’s own `cuda` feature already links the required static libraries. The custom `build.rs` is needed only if you provide hand‑tuned kernels. The specification above demonstrates the pattern explicitly.

## 2. Data Ingestion & Curation Subsystem

This subsystem runs asynchronously, fetches Python files from HuggingFace Parquet datasets, validates and deduplicates them, trains a BPE tokenizer, and produces a contiguous `u16` binary file memory‑mapped for zero‑copy streaming.

### 2.1. Sourcing & Stream Decoding

We stream Parquet files from a dataset like `bigcode/the-stack-v2` using `reqwest` and `parquet`/`arrow`. Decompression is done on‑the‑fly with pinned memory allocations (Arrow buffers can be page‑aligned).

```rust
use arrow::record_batch::RecordBatch;
use parquet::arrow::ParquetRecordBatchStreamBuilder;
use tokio::io::AsyncReadExt;

async fn stream_parquet(url: &str) -> anyhow::Result<impl Stream<Item = RecordBatch>> {
    let response = reqwest::get(url).await?;
    let bytes = response.bytes().await?;
    let cursor = std::io::Cursor::new(bytes);
    let builder = ParquetRecordBatchStreamBuilder::new(cursor).await?;
    let stream = builder.build()?;
    Ok(stream)
}
```

### 2.2. AST Validation & Filtering with `tree-sitter-python`

Each raw source string is parsed into a CST. Files with syntax errors, <100 bytes, >50% comment lines, or containing auto‑generated boilerplate (e.g. `# Auto-generated by`) are discarded.

```rust
use tree_sitter::{Parser, Language};
use tree_sitter_python::language;

fn is_valid_python(source: &str) -> bool {
    let mut parser = Parser::new();
    parser.set_language(&language()).expect("Error loading Python grammar");
    let tree = parser.parse(source, None);
    tree.is_some() // None means syntax error
}

fn filter_file(content: &str) -> bool {
    if content.len() < 100 {
        return false;
    }
    let lines: Vec<&str> = content.lines().collect();
    let comment_lines = lines.iter()
        .filter(|l| l.trim_start().starts_with('#'))
        .count();
    if (comment_lines as f64 / lines.len() as f64) > 0.5 {
        return false;
    }
    if content.contains("Auto-generated by") { // simplistic boilerplate check
        return false;
    }
    is_valid_python(content)
}
```

### 2.3. MinHash Deduplication (Parallelised with `rayon`)

We compute a MinHash signature (e.g. 128 hash functions) for each file and reject those whose Jaccard similarity exceeds 0.85 with any already‑accepted file. Implementation uses `rayon` for parallel shingling and signature generation; the comparison step uses a spatial index (e.g. LSH banding) or an approximate nearest neighbour structure to stay within memory.

High‑level sketch:

```rust
use rayon::prelude::*;
use std::collections::HashSet;

fn minhash_dedup(docs: Vec<&str>, threshold: f64) -> Vec<String> {
    // 1. Shingle each doc and compute MinHash signatures in parallel
    let signatures: Vec<[u64; 128]> = docs.par_iter()
        .map(|doc| compute_minhash_signature(doc, 128))
        .collect();
    // 2. LSH indexing & pairwise comparison (simplified here)
    let mut keep = HashSet::new();
    for (i, sig) in signatures.iter().enumerate() {
        let mut is_dup = false;
        for &j in &keep {
            if jaccard_estimate(&sig, &signatures[j]) > threshold {
                is_dup = true;
                break;
            }
        }
        if !is_dup { keep.insert(i); }
    }
    keep.into_iter().map(|i| docs[i].to_owned()).collect()
}
```

### 2.4. Tokenizer Training & Serialization

We collect a 2 GB subset of the deduplicated clean Python code, train a BPE tokenizer (vocab size 32000) with the `tokenizers` crate, then convert the entire corpus into `u16` token IDs and write them to a binary file.

```rust
use tokenizers::tokenizer::{Tokenizer, Result};
use tokenizers::models::bpe::BPE;
use tokenizers::decoders::byte_level::ByteLevel;
use tokenizers::processors::byte_level::ByteLevelProcessing;

fn train_tokenizer(texts: Vec<String>) -> Tokenizer {
    let mut tokenizer = Tokenizer::new(BPE::default());
    tokenizer.with_decoder(ByteLevel::new());
    tokenizer.with_processor(ByteLevelProcessing::new());
    let trainer = tokenizers::trainers::BpeTrainer::builder()
        .vocab_size(32_000)
        .min_frequency(2)
        .special_tokens(vec!["<|endoftext|>".into()])
        .build();
    tokenizer.train(&trainer, texts).unwrap();
    tokenizer
}

fn tokenize_and_write(tokenizer: &Tokenizer, corpus: Vec<String>, path: &str) -> std::io::Result<()> {
    let mut all_ids = Vec::with_capacity(2_000_000_000);
    for doc in corpus {
        let encoding = tokenizer.encode(doc, false).unwrap();
        all_ids.extend(encoding.get_ids().iter().map(|&id| id as u16));
    }
    // Write to file; then mmap later.
    let mut file = std::fs::File::create(path)?;
    let slice = unsafe {
        std::slice::from_raw_parts(all_ids.as_ptr() as *const u8, all_ids.len() * 2)
    };
    std::io::Write::write_all(&mut file, slice)?;
    Ok(())
}
```

The binary file is then opened with `memmap2::Mmap` to get a `&[u16]` that can be sliced into sequence batches and fed directly to GPU tensors with `candle::Tensor::from_raw_buffer`.

## 3. Model Architecture (~135M Llama‑Style Decoder)

All components are implemented in pure Rust using `candle-core` for tensor ops. The configuration matches the specification: `d_model=768`, `n_layer=12`, `n_head=12` (query heads), `n_kv_head=4`, `d_ff=2048`, `vocab_size=32000`, `max_seq_len=2048`.

### 3.1. Rotary Position Embeddings (RoPE)

Pre‑compute sin/cos for position indices up to `max_seq_len` and apply to query/key tensors, splitting heads and halving dimensions per the standard Llama pattern.

```rust
use candle_core::{Device, Tensor};

fn precompute_freqs_cis(dim: usize, end: usize, theta: f64) -> Tensor {
    let freqs = (0..dim / 2).map(|i| 1.0 / (theta.powf(2.0 * i as f64 / dim as f64)));
    let t = Tensor::arange(0, end as i64, &Device::Cpu).to_dtype(candle_core::DType::F32);
    let freqs = Tensor::from_vec(freqs.collect(), (dim/2,), &Device::Cpu);
    let freqs = t.outer(&freqs); // [end, dim/2]
    Tensor::cat(&[freqs.cos(), freqs.sin()], 1) // store as [cos; sin]
}

fn apply_rotary_emb(x: &Tensor, freqs_cis: &Tensor) -> Tensor {
    let (x_cos, x_sin) = x.chunk(2, 1);
    let freqs_cos = freqs_cis.narrow(1, 0, freqs_cis.dim(1)?/2);
    let freqs_sin = freqs_cis.narrow(1, freqs_cis.dim(1)?/2, freqs_cis.dim(1)?/2);
    let rotated = (x_cos * freqs_cos - x_sin * freqs_sin).concat(&(x_cos * freqs_sin + x_sin * freqs_cos), 1);
    rotated
}
```

### 3.2. Grouped‑Query Attention (GQA) with FlashAttention

The attention module receives `q, k, v` projections. To match GQA, after projecting keys/values with `n_kv_head=4`, they are repeated `n_rep = n_head / n_kv_head = 3` times. The full attention computation leverages `candle_nn::ops::flash_attn` (if available) or a manual efficient attention that uses `candle_nn::ops::scaled_dot_product_attention` with a causal mask.

```rust
use candle_core::{Tensor, DType};
use candle_nn::{Linear, Module};

struct Attention {
    q_proj: Linear,
    k_proj: Linear,
    v_proj: Linear,
    o_proj: Linear,
    n_head: usize,
    n_kv_head: usize,
    head_dim: usize,
    scale: f64,
    rope_freqs: Tensor,
}

impl Attention {
    fn forward(&self, x: &Tensor, mask: Option<&Tensor>) -> Result<Tensor> {
        let (b, t, _) = x.dims3()?;
        let q = self.q_proj.forward(x)?.reshape((b, t, self.n_head, self.head_dim))?.transpose(1, 2)?;
        let k = self.k_proj.forward(x)?.reshape((b, t, self.n_kv_head, self.head_dim))?.transpose(1, 2)?;
        let v = self.v_proj.forward(x)?.reshape((b, t, self.n_kv_head, self.head_dim))?.transpose(1, 2)?;

        // Apply RoPE to Q and K
        let q = apply_rotary_emb(&q, &self.rope_freqs)?;
        let k = apply_rotary_emb(&k, &self.rope_freqs)?;

        // Repeat KV heads
        let n_rep = self.n_head / self.n_kv_head;
        let k = k.repeat((1, n_rep, 1, 1))?;
        let v = v.repeat((1, n_rep, 1, 1))?;

        // Use flash attention if compiled; fallback to manual matmul
        #[cfg(feature = "flash-attn")]
        let attn_out = candle_nn::ops::flash_attn(&q, &k, &v, self.scale as f32, true)?;
        #[cfg(not(feature = "flash-attn"))]
        let attn_out = {
            let weights = (q.matmul(&k.t()?)? * self.scale)?;
            let weights = match mask {
                Some(m) => (weights + m)?,
                None => weights,
            };
            let weights = candle_nn::ops::softmax_last_dim(&weights)?;
            weights.matmul(&v)?
        };

        let attn_out = attn_out.transpose(1, 2)?.reshape((b, t, self.n_head * self.head_dim))?;
        self.o_proj.forward(&attn_out)
    }
}
```

### 3.3. Full Decoder Layer & Model

A single layer combines RMSNorm, the GQA attention, residual, then another RMSNorm, a SwiGLU feed‑forward, and a final residual.

```rust
struct DecoderLayer {
    attention_norm: candle_nn::RmsNorm,
    attention: Attention,
    ffn_norm: candle_nn::RmsNorm,
    gate_proj: Linear,   // SwiGLU gate
    up_proj: Linear,     // SwiGLU up
    down_proj: Linear,   // output
}

impl Module for DecoderLayer {
    fn forward(&self, x: &Tensor) -> Result<Tensor> {
        let residual = x;
        let x = self.attention_norm.forward(x)?;
        let x = self.attention.forward(&x, None)?;
        let x = (x + residual)?;

        let residual = &x;
        let x = self.ffn_norm.forward(&x)?;
        let gate = self.gate_proj.forward(&x)?.silu()?;
        let up = self.up_proj.forward(&x)?;
        let x = (&gate * &up)?;
        let x = self.down_proj.forward(&x)?;
        x + residual
    }
}

struct Llama {
    tok_embeddings: candle_core::Embedding,
    layers: Vec<DecoderLayer>,
    norm: candle_nn::RmsNorm,
    lm_head: Linear,
}

impl Llama {
    fn forward(&self, input_ids: &Tensor) -> Result<Tensor> {
        let (_b, seq_len) = input_ids.dims2()?;
        let mut x = self.tok_embeddings.forward(input_ids)?;
        for layer in &self.layers {
            x = layer.forward(&x)?;
        }
        let x = self.norm.forward(&x)?;
        self.lm_head.forward(&x)
    }
}
```

This design yields approximately 135 M parameters (including embedding and LM head weight tying). The `RmsNorm` uses `epsilon = 1e-5`.

## 4. Optimised Pre‑Training Loop & VRAM Management

The loop is engineered to keep the GPU saturated while never exceeding 28 GB of the available 32 GB. We use `bf16` for weights and activations, master weights in `fp32`, and `AdamW` with decoupled weight decay.

### 4.1. Data Loader with Memory‑Mapped Tokens

The binary file of token IDs is memory‑mapped and sliced into fixed‑length sequences of `2048` tokens. Overlapping or contiguous partition can be used. For simplicity, we partition the entire file into non‑overlapping sequences and drop the last incomplete block.

```rust
use memmap2::Mmap;
use candle_core::{Device, Tensor};

struct MmapDataLoader {
    mmap: Mmap,
    seq_len: usize,
    total_tokens: usize,
    device: Device,
}

impl MmapDataLoader {
    fn open(path: &str, device: Device) -> std::io::Result<Self> {
        let file = std::fs::File::open(path)?;
        let mmap = unsafe { Mmap::map(&file)? };
        let total_tokens = mmap.len() / 2; // u16 -> 2 bytes
        Ok(Self { mmap, seq_len: 2048, total_tokens, device })
    }

    fn num_batches(&self) -> usize {
        self.total_tokens / self.seq_len
    }

    fn get_batch(&self, idx: usize) -> Result<Tensor> {
        let start = idx * self.seq_len * 2;
        let end = start + self.seq_len * 2;
        let slice = &self.mmap[start..end];
        let u16_slice: &[u16] = unsafe {
            std::slice::from_raw_parts(slice.as_ptr() as *const u16, self.seq_len)
        };
        Tensor::from_raw_buffer(
            u16_slice,
            candle_core::DType::U16,
            &[self.seq_len],
            &self.device,
        )?.to_dtype(candle_core::DType::I64) // convert to long for embedding
    }
}
```

### 4.2. Mixed Precision & Optimizer

Model weights are loaded in `bf16`. Master parameters are maintained in `fp32` inside the optimizer. `candle_nn::AdamW` is configured with `beta1=0.9`, `beta2=0.95`, `weight_decay=0.1` and learning rate scheduled.

```rust
let mut model = Llama::new(...).to_device(&device)?.to_dtype(DType::BF16)?;
let adamw = candle_nn::AdamW::new(model.variables(), candle_nn::ParamsAdamW {
    lr: 2.5e-3,
    beta1: 0.9,
    beta2: 0.95,
    wd: 0.1,
    ..Default::default()
})?;
```

### 4.3. Training Loop with Throughput Logging & LR Schedule

We use a global batch size of `64` sequences (131 072 tokens). Gradient accumulation is set to 1 if memory permits; otherwise a smaller micro‑batch with accumulation is used. The following loop runs for `total_tokens / (micro_batch * seq_len * accum) = 2e9 / global_batch` steps.

```rust
use std::time::Instant;

fn cosine_schedule(step: usize, warmup_steps: usize, total_steps: usize, peak_lr: f64, min_lr: f64) -> f64 {
    if step < warmup_steps {
        peak_lr * step as f64 / warmup_steps as f64
    } else {
        let progress = (step - warmup_steps) as f64 / (total_steps - warmup_steps) as f64;
        min_lr + 0.5 * (peak_lr - min_lr) * (1.0 + f64::cos(std::f64::consts::PI * progress))
    }
}

fn train(model: &mut Llama, loader: &MmapDataLoader, device: &Device) -> anyhow::Result<()> {
    let global_batch = 64;
    let micro_batch = 64;          // fits comfortably in 28GB
    let accum_steps = 1;           // gradient accumulation if needed
    let total_tokens = 2_000_000_000u64;
    let seq_len = 2048;
    let steps = total_tokens / (global_batch as u64 * seq_len as u64);
    let warmup = 1000;
    let mut optimizer = ...; // AdamW instance

    let mut total_time = 0.0;
    let start = Instant::now();
    for step in 0..steps {
        let lr = cosine_schedule(step as usize, warmup, steps as usize, 2.5e-3, 2.5e-5);
        optimizer.set_lr(lr);

        let batch_start = Instant::now();
        let idx = (step as usize * global_batch / micro_batch) % loader.num_batches();
        let input = loader.get_batch(idx)?;   // shape [2048]
        let target = loader.get_batch((idx + 1) % loader.num_batches())?; // next‑token prediction

        // Forward (mixed precision: bf16)
        let logits = model.forward(&input.unsqueeze(0)?)?; // [1, 2048, vocab]
        let loss = candle_nn::loss::cross_entropy(&logits.squeeze(0)?, &target)?;

        // Backward
        optimizer.backward_step(&loss)?;

        total_time += batch_start.elapsed().as_secs_f64();
        if step % 10 == 0 {
            let tokens = (step + 1) as u64 * global_batch as u64 * seq_len as u64;
            let elapsed = start.elapsed().as_secs_f64();
            let throughput = tokens as f64 / elapsed;
            println!("step {step}/{steps} | loss {:.4} | lr {:.2e} | tokens/s {:.0}", loss.to_scalar::<f32>()?, lr, throughput);
        }
    }
    Ok(())
}
```

**VRAM Management:**
- Model weights bf16: ~270 MB
- Master params fp32: ~540 MB
- Optimizer states (adam m & v fp32): ~1.08 GB
- Activations with micro‑batch 64 × 2048 × 768 × 2 bytes ≈ 201 MB, plus attention intermediates
- FlashAttention drastically reduces the memory of the QK^T matrix.
Total VRAM usage stays well below 28 GB, leaving headroom for CUDA context and caches. Peak throughput on an RTX 5090 with this architecture is expected to exceed 70 k tokens/s.

The specification outlines a complete, zero‑Python pipeline for pre‑training a 135M‑parameter Llama model on a single RTX 5090. The build system handles MSVC/CUDA linkage, the data subsystem produces a memory‑mapped token stream, the model module explicitly implements GQA and RoPE, and the training loop maximises tensor core utilisation while maintaining stable memory consumption.
