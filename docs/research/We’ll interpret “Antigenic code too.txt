We’ll interpret “Antigenic code tool” as an agentic coding assistant (e.g., a CLI AI such as Claude Code, Aider, or similar) that can generate code, run tests, and commit in a loop. The following is an ordered, self‑contained list of prompts that you would feed to such a tool, step by step, to plan, implement, verify, and commit the entire pure‑Rust LLM pre‑training pipeline. Each prompt includes explicit “verify” instructions, and you should tell the tool to `git commit` after each successful step.

---

### 0. Pre‑requisites
Make sure you have:
- Windows 11, MSVC toolchain, CUDA 12.x, `git`
- The “Antigenic code tool” configured to run shell commands, edit files, and compile Rust (`cargo build`).
- A working directory initialized with `cargo new rust-llm-pretrain`.

---

### Ordered Prompt List

1. **Initialize project structure, dependencies, and CUDA build integration**
   - Prompt:  
     “Edit `Cargo.toml` to include all dependencies listed in the spec (`candle-core` with cuda+bf16 features, `candle-nn`, `tokenizers`, `reqwest`, `arrow`/`parquet`, `tree-sitter` + `tree-sitter-python`, `memmap2`, `rayon`, `indicatif`, `tokio`, `anyhow`, `clap`). Create a `build.rs` that locates the CUDA toolkit via the `CUDA_PATH` environment variable, links `cublas`, `cudnn`, `curand`, `cudart`, and compiles a placeholder CUDA kernel from `kernels/flash_attn_fwd.cu` (write a minimal stub that does nothing but compiles with `sm_90a`). After writing, run `cargo check` to confirm the build system works. Then commit with message ‘feat: project setup and CUDA build linkage’.”

2. **Implement Parquet data streaming and basic filtering skeleton**
   - Prompt:  
     “Create a module `src/data/ingestion.rs`. Implement an async function that downloads a Parquet file from a given URL using `reqwest`, parses it with `parquet` and `arrow`, and returns a stream of `RecordBatch` (or raw string content). Add a placeholder filter function `filter_file(content: &str) -> bool` that currently just returns `content.len() > 100`. Write a `#[tokio::test]` that uses a small sample Parquet (or creates one in‑memory) and verifies that rows are returned. Run `cargo test` to verify. Commit with message ‘feat: async Parquet ingestion skeleton’.”

3. **Tree‑sitter Python AST validation and filtering rules**
   - Prompt:  
     “In `src/data/validation.rs`, implement `is_valid_python(source: &str) -> bool` using `tree_sitter_python`. Extend the `filter_file` function in `ingestion.rs` to reject files with syntax errors, files where comment lines exceed 50%, files under 100 bytes, and files containing the substring ‘Auto-generated by’ (simplistic boilerplate detection). Move the filtering logic to `validation.rs` and expose a single `pub fn should_keep(content: &str) -> bool`. Write unit tests with both valid and invalid Python snippets. Run `cargo test` and commit with message ‘feat: tree-sitter AST validation and filtering rules’.”

4. **MinHash deduplication pipeline**
   - Prompt:  
     “Create `src/data/dedup.rs`. Implement `compute_minhash_signature(text: &str, num_hashes: usize) -> Vec<u64>` using multiple hash functions. Write a function `deduplicate(docs: Vec<String>, threshold: f64) -> Vec<String>` that uses parallel `rayon` for signature computation, then applies LSH or pairwise comparison to remove Jaccard‑similar (>0.85) duplicates. Add a test with artificially duplicated documents. Ensure all tests pass and commit with message ‘feat: MinHash deduplication module’.”

5. **BPE tokenizer training and corpus tokenization**
   - Prompt:  
     “Create `src/data/tokenizer.rs`. Write a function `train_tokenizer(texts: Vec<String>) -> Tokenizer` that uses the `tokenizers` crate’s BPE trainer with `vocab_size=32000`, `min_frequency=2`, and special token `‘<|endoftext|>’`. Then implement `tokenize_and_write(tokenizer, corpus, path: &str)` that tokenizes the whole corpus to `u16` ids and writes them to a binary file. Write an integration test that trains on a tiny Python text, writes a token file, reads it back, and checks the length. Commit with message ‘feat: BPE tokenizer training and u16 serialization’.”

6. **Create the final data pipeline script and generate the 2B‑token corpus**
   - Prompt:  
     “Create `src/bin/build_corpus.rs`. It should: (1) accept a list of Parquet URLs, (2) stream and filter all files using the previous modules, (3) apply deduplication, (4) train the tokenizer on a 2GB subset, (5) tokenize the entire deduplicated set and write the contiguous u16 binary file. Also, memory‑map the resulting file with `memmap2` and print the total number of tokens. Run this script on a small set of sample files to verify end‑to‑end functionality (you may mock the network fetch or use a local sample). Commit with message ‘feat: end‑to‑end data pipeline binary’.”

7. **Define model configuration and RoPE utilities**
   - Prompt:  
     “Create `src/model/config.rs` with a struct `LlamaConfig` that sets `d_model=768`, `n_layer=12`, `n_head=12`, `n_kv_head=4`, `d_ff=2048`, `vocab_size=32000`, `max_seq_len=2048`, `rms_norm_eps=1e-5`, `rope_theta=10000.0`. In `src/model/rope.rs`, implement `precompute_freqs_cis` and `apply_rotary_emb` using `candle` tensors. Add a test that checks the shape and that applying RoPE preserves the vector norm for a small input. Commit with message ‘feat: model config and RoPE implementation’.”

8. **Implement Grouped‑Query Attention with FlashAttention fallback**
   - Prompt:  
     “Create `src/model/attention.rs`. Define the `Attention` struct with linear projections, and implement `forward` that projects Q/K/V, applies RoPE, repeats KV heads for GQA (3:1 ratio), and uses `candle_nn::ops::flash_attn` if available, otherwise scaled dot‑product with causal mask. Write a test that runs a forward pass with a dummy input of shape `(2, 32, 768)` and verifies the output shape is correct. Commit with message ‘feat: GQA attention with FlashAttention fallback’.”

9. **Assemble decoder layer and full Llama model**
   - Prompt:  
     “Create `src/model/decoder.rs`. Implement `DecoderLayer` with pre‑attention RMSNorm, the `Attention` block, residual, pre‑FFN RMSNorm, SwiGLU (gate/up projection and SiLU), and a final linear projection. Then in `src/model/llama.rs`, define the `Llama` struct with a token embedding, a stack of 12 `DecoderLayer`s, final RMSNorm, and LM head (tied weights optional). Write a forward pass for the entire model. Add a test with a random input token sequence of length 2048 and verify that the output shape is `(batch, seq_len, vocab_size)`. Commit with message ‘feat: full Llama decoder model (135M)’.”

10. **Memory‑mapped data loader for training**
    - Prompt:  
      “Create `src/training/data_loader.rs`. Implement `MmapDataLoader` that opens the binary u16 file, memory‑maps it, and returns a non‑overlapping window of `seq_len` tokens as a `Tensor` on the GPU. Also implement a method `next_batch` that provides input and target (shifted by one). Write a test using a small dummy file that checks the returned tensors have the right dimensions and that `input[1:] == target[:-1]`. Commit with message ‘feat: memory‑mapped token data loader’.”

11. **Optimizer setup and cosine LR scheduler**
    - Prompt:  
      “In `src/training/optimizer.rs`, create a function `build_adamw(model_vars, lr) -> AdamW` with `beta1=0.9, beta2=0.95, weight_decay=0.1`. Implement `cosine_schedule(step, warmup, total_steps, peak_lr, min_lr)` that returns the learning rate for a given step. Write a unit test that prints a few values to verify the warmup and decay shape. Commit with message ‘feat: AdamW optimizer and cosine LR schedule’.”

12. **Complete training loop with mixed precision, gradient accumulation, and throughput logging**
    - Prompt:  
      “Create `src/bin/train.rs`. It should: load the model in `bf16` on the GPU, set up the data loader, create the AdamW optimizer with master weights in `fp32`. The loop runs for `total_tokens / global_batch` steps with `global_batch=64` (micro‑batch and accumulation adjusted to fit ~28GB VRAM). On each step: (1) set LR via cosine schedule, (2) compute loss using cross‑entropy (with optional ignore index for padding), (3) backward pass, (4) optimizer step, (5) log loss, LR, and tokens/sec every 10 steps. Use `indicatif` for a progress bar. Add a `#[cfg(test)]` integration test that runs training for 5 steps on a tiny synthetic token file (e.g., 1000 random tokens) to verify no OOM, loss decreases, and throughput is printed. Commit with message ‘feat: full pre‑training loop with bf16 mixed precision’.”

13. **Final verification: end‑to‑end training on a small sample**
    - Prompt:  
      “Run the complete pipeline on a scaled‑down dataset (e.g., 1 million tokens) by executing `cargo run --bin build_corpus` with a sample Parquet, then `cargo run --bin train` with a reduced total‑tokens argument. Confirm that the training loss decreases, that throughput is logged, and that there is no crash. Once verified, commit any remaining files (like `.gitignore`, README placeholder) and tag the commit as ‘v0.1.0’ with the message ‘chore: successful end‑to‑end dry‑run’.”

---

After completing the above loop, the project will contain a fully functional, pure‑Rust LLM pre‑training pipeline. You can then iterate on hyperparameters, kernel optimizations, or FlashAttention‑3 integration by creating follow‑up prompts. The pattern of “implement → test → verify → commit” ensures the tool maintains a working state at every step.
